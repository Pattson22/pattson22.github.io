\section{Introduction}
This report documents the design and development of my computer science portfolio, created as part of the B201 Computer Science Lab module at GISMA University of Applied Sciences. The portfolio is a personal website, hosted on GitHub Pages, that presents my skills, projects, and credentials to a specific audience: hiring managers recruiting for working student (Werkstudent) cloud engineering positions in Germany.

I chose that audience deliberately because it shaped every decision I made. When I looked through real job listings on platforms such as Hays and StepStone, the same requirements appeared again and again: AWS, Terraform or other Infrastructure as Code tooling, Docker, CI/CD pipelines, Linux fundamentals, and a candidate who can document and explain what they have built. A portfolio aimed at that market therefore cannot simply list technologies. It has to prove, with evidence, that I can build, automate, secure, monitor, and clearly communicate cloud infrastructure.

\section{Portfolio Design and Structure}

\subsection{Website Structure}
The website is a single-page application divided into clearly labelled sections that a visitor scrolls through in a deliberate order: a hero introduction, an ``About'' section, certifications, featured projects, a live GitHub feed, technical exercises, and contact details. The hero section states who I am and what I do in one glance, with a short animated terminal that signals my comfort in a command-line, infrastructure context.

\subsection{GitHub Repository Structure}
The repository is organised so that anyone can navigate it without explanation. The website files (\texttt{index.html}, \texttt{style.css}, \texttt{script.js}) sit at the root, as GitHub Pages expects. Supporting material is grouped into purpose-named folders: \texttt{/assets} for images and architecture diagrams, \texttt{/cv} for LaTeX CV and compiled PDF, \texttt{/exercises} for the three technical demonstrations, and \texttt{/report} for this document. A single top-level \texttt{README.md} ties everything together.

\subsection{Design Decisions}
I chose a single-page layout because recruiters typically spend very little time on any one portfolio. A single, scannable page removes navigation friction and lets a reader reach the projects in seconds. I added a dark and light mode toggle for accessibility and personal preference; the choice is saved to \texttt{localStorage}. I selected an AWS-orange accent colour deliberately to visually tie the site to the cloud platform I specialise in. I hosted on GitHub Pages because it is free and integrates directly with the repository.

\section{Tools and Technologies}
I kept the technology stack deliberately lean, choosing tools that match the job rather than the most fashionable option.

\begin{itemize}[leftmargin=*]
  \item \textbf{Frontend:} HTML5, CSS3 (custom properties, Flexbox, Grid), vanilla JavaScript.
  \item \textbf{Hosting and VCS:} Git, GitHub, GitHub Pages.
  \item \textbf{Documentation and CV:} LaTeX (Overleaf).
  \item \textbf{Diagrams:} draw.io (diagrams.net).
\end{itemize}

\section{Portfolio Content}

\subsection{Featured Projects}
I curated five projects and ordered them by how directly they map onto German cloud engineering requirements.

\begin{enumerate}
  \item \textbf{Multi-tier Cloud Application} --- three-tier AWS environment provisioned with Terraform, containerised with Docker, deployed via GitHub Actions.
  \item \textbf{Highly Available Crypto API} --- multi-AZ design with ALB and Auto Scaling.
  \item \textbf{MLOps API Infrastructure} --- reproducible containerised deployment for ML serving.
  \item \textbf{Group Chat Application} --- full-stack real-time concurrency.

\section{Critical Evaluation}

\subsection{Strengths}
The portfolio's dynamic GitHub integration keeps the projects section current. The design is clean and fully responsive. The cloud-focused branding (AWS-orange accent, terminal motif) and repository organisation demonstrate operational discipline and system thinking.

\subsection{Weaknesses}
Current limitations include: no contact form, project descriptions that could be deeper, only one displayed certification, no blog or technical writing, no visitor analytics, and the site is English-only (no German translation).

\section{Future Improvements}
Planned improvements:
\begin{itemize}[leftmargin=*]
  \item Add a working contact form and lightweight visitor analytics.
  \item Add further certifications (HashiCorp Terraform Associate, AWS Developer).
  \item Start a short technical blog and expand projects into detailed case studies.
  \item Add a German language toggle.
\end{itemize}

\section{Conclusion}
Building this portfolio taught me that presenting technical work well is a discipline in its own right. The result is a focused, honest, and well-organised portfolio that demonstrates the skills a working student cloud engineering role in Germany demands.
